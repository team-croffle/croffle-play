# Release notes — `.ai/release/`

`.ai/release/<version>_<Release|Pre-Release>.md` is the exact body passed to
`gh release edit --notes-file`. It is not a procedure document: no commands,
run URLs, or QA logs (those go to `.ai/history/` and `.ai/test/`).

| Kind        | Title                     | File                                    |
| ----------- | ------------------------- | --------------------------------------- |
| Stable      | `Release vX.Y.Z`          | `.ai/release/X.Y.Z_Release.md`          |
| Pre-release | `Pre-Release vX.Y.Z-rc.A` | `.ai/release/X.Y.Z-rc.A_Pre-Release.md` |

The workflow already sets the title and an `Images:` block (one line per app
with its digest); keep that block at the top of the body.

## Changelogs section

The last section is generated by GitHub:

```
gh api -X POST repos/{owner}/{repo}/releases/generate-notes \
  -f tag_name=vX.Y.Z-rc.A -f previous_tag_name=<previous tag> --jq .body
```

Rename its `## What's Changed` heading to `## Changelogs` and keep the rest.
`previous_tag_name` is the previous tag in semver order (for a stable release:
the previous stable tag, so the list spans every rc).
